Client trust installation

Use the Download CA (PEM) button in the Root certificate authority card above to save the file, then install it on every client that should be inspected. Without this step, browsers and applications will show certificate warnings on every HTTPS site. Pick the section that matches the client operating system.

Linux — Debian / Ubuntu

# Copy the CA into the system trust store
sudo cp enterprise-ai-ids-ca.crt /usr/local/share/ca-certificates/enterprise-ai-ids-ca.crt

# Refresh the trust store
sudo update-ca-certificates

# Verify (should print the CA subject)
awk -v cmd='openssl x509 -noout -subject' \
  '/BEGIN/{close(cmd)};{print | cmd}' \
  < /etc/ssl/certs/ca-certificates.crt | grep "Enterprise AI IDS"

Linux — Fedora / RHEL / CentOS

# Copy the CA into the anchors directory
sudo cp enterprise-ai-ids-ca.crt /etc/pki/ca-trust/source/anchors/

# Refresh the trust store
sudo update-ca-trust

# Verify
trust list | grep -A2 "Enterprise AI IDS"

Linux — Arch

sudo cp enterprise-ai-ids-ca.crt /etc/ca-certificates/trust-source/anchors/
sudo trust extract-compat

macOS

# Add the CA to the System keychain
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain \
  enterprise-ai-ids-ca.crt

# Verify
security find-certificate -c "Enterprise AI IDS" \
  /Library/Keychains/System.keychain

GUI alternative: open the .crt file with Keychain Access, add it to the System keychain, then double-click the entry and set When using this certificate to Always Trust. Administrator credentials will be required.

Windows (10 / 11 / Server)

# Run in an elevated PowerShell or cmd.exe

:: Import into the Local Machine Root store
certutil -addstore -f "ROOT" enterprise-ai-ids-ca.crt

:: Verify
certutil -store "ROOT" | findstr /I "Enterprise AI IDS"

GUI alternative: double-click the .crt file → Install Certificate → Local Machine → Place all certificates in the following store → Trusted Root Certification Authorities.

Firefox (all platforms)

Firefox uses its own certificate store and does not automatically trust the system store on Linux. Do one of the following. 

# Option 1 — trust the system store (simplest, works after any OS-level install)
1. Open about:config
2. Set security.enterprise_roots.enabled = true
3. Restart Firefox

# Option 2 — import the CA directly
1. Open about:preferences#privacy
2. Scroll to "Certificates" → click "View Certificates"
3. Go to the "Authorities" tab → click "Import…"
4. Select enterprise-ai-ids-ca.crt
5. Check "Trust this CA to identify websites" → OK

Chrome / Edge / Safari

Chrome and Edge on Windows and macOS use the operating system trust store, so the OS-level steps above cover them. Safari uses the macOS keychain. On Linux, Chrome uses the NSS store — run certutil against the NSS database if the system-wide install does not take effect: 

# Install libnss3-tools first (Debian/Ubuntu: nss-tools)
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "Enterprise AI IDS" \
  -i enterprise-ai-ids-ca.crt
Verification checklist. After installing the CA on a client, open any HTTPS site (for example https://example.com):
  • No certificate warning. The padlock shows normally.
  • Issuer shows "Enterprise AI IDS Root CA". Click the padlock → Certificate → check the issuer.
  • The connection appears in the IDS. Open /dashboard → log search, and look for a row with decrypted=true and ml_skipped_no_features in the reasons column.

If the padlock shows but the connection does not appear in the dashboard, TLS interception is not actually happening — the traffic is bypassing the redirect. Check the iptables rules with sudo python -m ssl_inspect.iptables status and confirm that the client is not excluded by a RETURN rule.

Enable interception

These commands redirect TCP/443 into the sslsplit interceptor. Run as root. The install command is idempotent. 

# Redirect 443 → interceptor
sudo python -m ssl_inspect.iptables install

# Exclude the IDS host itself (adjust IP)
sudo iptables -t nat -I PREROUTING 1 -s <IDS_HOST_IP> -j RETURN

# Check current state
sudo python -m ssl_inspect.iptables status

# When done
sudo python -m ssl_inspect.iptables remove

How bypass works: the rules above are enforced at the iptables layer. Each enabled SNI pattern becomes a -m string match on the first packet of each connection; if it matches, the connection bypasses the redirect to sslsplit and reaches the real server directly. This means SNI bypass works even for certificate-pinned services, at the cost of the interception no longer seeing those connections. IP and CIDR rules apply the same logic but match on the source address instead of the ClientHello.
